The Exposed Employee File

TechCorp's Employee Document Portal may be leaking internal files that were never meant to be public. Investigate how documents are loaded and find the sensitive file that shouldn't be reachable.

Task 1 Briefing ▾

It is 9:00 AM at TechCorp.

Alex has already completed his first security investigation. Now Sarah, the Security Team Lead, hands him a new assignment.

Sarah: "Several employees reported that internal files are appearing on the employee portal. These documents should not be publicly accessible. Investigate the portal and find out what is wrong."

TechCorp runs an internal Employee Document Portal. Employees can log in to view their own documents, such as profiles, training records, and payslips.

During a first look, Alex notices something interesting: documents are loaded using predictable file paths. His mission is to determine whether a sensitive document can be accessed without the right protection — and recover the flag hidden inside it.

Sarah: "Logging in proves who you are. It does not automatically mean every file on the server is safe to hand out."

Alex decides not to assume the portal is secure. His task is to investigate how the application serves files.

Task 2 Mission 1 — Log In to the Portal ▾

Alex starts with the Employee account provided by Sarah.

username: alex
password: Alex@123

Your task

  1. Log in to the TechCorp Employee Document Portal.
  2. Confirm that the login succeeds.
  3. Note your Employee ID shown after login.
Task 3 Mission 2 — Explore the Documents ▾

Open My Documents. As a normal employee, Alex can see:

DocumentType
profile.txtPersonal profile
training.pdfTraining record
payslip.pdfPayslip

Your task — open each document and pay attention to the URL:

  • What path does the browser request when you open a document?
  • Which parts of that path look predictable?
  • Could you guess the path to a file that isn't listed here?
Task 4 Mission 3 — Inspect the File Paths ▾

Instead of only opening the files he was given, Alex studies how the portal builds document URLs. A document loads from something like:

/files/EMP1042/profile.txt

Your task — use your browser's Developer Tools (Network tab) or just edit the address bar to investigate the file paths. Look for:

  • The structure of the URL (folder + filename)
  • Whether the folder name is predictable
  • What happens if you request a folder instead of a file
  • Whether the server ever refuses to hand over a file

Goal — determine whether files outside your own folder can be reached through a predictable path.

💡 Don't guess the flag. Follow the evidence from the paths the application exposes.

Look carefully at how the document URL is constructed. It has two obvious parts: a folder (your employee ID) and a file name.
Check whether the file path follows a predictable pattern. Try removing the file name and requesting just the folder — e.g. /files/EMP1042/ — or go one level up to /files/ and see what the server returns.
Use Developer Tools → Network to watch the exact requests the browser makes when you open a document. The response to a directory request is especially interesting.
Browse the file store from /files/. You should see more than just your own folder. One folder was never meant to be on the employee portal at all — open it and read what's inside.
Task 5 Mission 4 — Find the Exposed File ▾

Alex realizes that authentication is working — he is logged in as a normal employee — but the file server hands out documents by path without checking whether they belong to him. Somewhere in the file store is an internal document that should never have been reachable.

Your task — locate the exposed sensitive document, open it, and read the hidden flag inside. Use only the provided lab environment.

Success condition — retrieve the sensitive file and submit the flag below.

Task 6 Mission 5 — Explain the Incident ▾

Alex reports his findings to Sarah.

Alex: "The login worked correctly, but the file server gave me a document that belongs to HR. It was sitting at a predictable path with no access control."

Sarah asks Alex to prove that he understands what happened.

Answer the following (for your own notes):

  1. What type of vulnerability did you discover?
  2. Why was the sensitive file accessible?
  3. What information was exposed?
  4. What is the flag?
  5. What security control should TechCorp implement?

🎓 What Alex Learned

🔎 Information Disclosure
An application unintentionally exposes information to people who should not have access to it.

🛡️ The Fix — Authorization & Secure Storage
Sensitive files must be protected with proper authorization and access controls, not just hidden behind a predictable path.

⭐ Key Lesson: authentication alone does not make every resource safe to expose. Sensitive resources need their own access controls.
